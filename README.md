# КБЖУ — калькулятор нормы и дневник питания

Веб-приложение: рассчитывает дневную норму калорий и БЖУ по параметрам пользователя и позволяет вести дневник питания с подсчётом съеденного и остатка до нормы.

Реализовано по ТЗ из ДЗ 3 (продуктовая идея «КБЖУ-калькулятор») и правилам из `.cursorrules` (ДЗ 2).

---

## Возможности

- **Расчёт нормы КБЖУ** — формула Миффлина–Сан Жеора с учётом пола, возраста, роста, веса, активности и цели. Норма не опускается ниже безопасного минимума (муж. 1500 / жен. 1200 ккал) и предупреждает об этом.
- **Дневник питания** — добавление продуктов в приёмы пищи (завтрак/обед/ужин/перекус), мгновенный пересчёт калорий и БЖУ за день, остаток до нормы.
- **Поиск продуктов и порции** — поиск по базе, выбор порции в граммах с пропорциональным пересчётом КБЖУ, предпросмотр до добавления.
- **Сводка дня** — кольцо прогресса калорий и прогресс-бары по белкам/жирам/углеводам; корректная обработка превышения нормы.
- **Персист** — данные сохраняются в браузере (localStorage) между сессиями.

## Стек

- **React 18 + TypeScript** (strict)
- **Vite 5** — сборка и dev-сервер с hot reload
- **Tailwind CSS 3** — стилизация, токены темы в `tailwind.config.js`
- **Vitest + React Testing Library** — тесты
- Архитектура — **Feature-Sliced Design**: `entities → features → pages → shared`

## Запуск

Нужен Node.js 18+.

```bash
# установка зависимостей
npm install

# режим разработки (http://localhost:5173)
npm run dev

# продакшен-сборка
npm run build

# просмотр собранной версии
npm run preview
```

## Тесты

```bash
npm test          # прогон один раз
npm run test:watch
```

Покрыто 21 тестом в 4 файлах: чистая логика расчёта нормы и порций, компонент онбординга и главный экран дня. Тесты включают позитивные сценарии и обработку ошибок (пустые поля, значения вне диапазона, безопасный минимум калорий, превышение нормы, пустой поиск).

## Адаптивность

Вёрстка mobile-first. Контент центрируется в колонке `max-w-md`; модалка поиска на мобильном открывается снизу (bottom sheet), на десктопе — по центру. Проверено от 360 px до десктопа.

## Обработка состояний

Каждый пользовательский ввод обрабатывает край: пустые и некорректные значения в онбординге, порция ≤ 0, пустой результат поиска, превышение нормы калорий (показывается спокойным индикатором без осуждения). Ошибки хранилища не роняют приложение.

## Backend (ДЗ 5)

Приложение подключено к бэкенду на **Supabase** (PostgreSQL + Auth + авто REST API + RLS). Дневник и профиль хранятся на сервере, привязаны к аккаунту пользователя.

### Что нужно для запуска с бэкендом
1. Создать проект на [supabase.com](https://supabase.com).
2. В **SQL Editor** выполнить `supabase/migrations/0001_init.sql`.
3. В **Authentication → Providers** включить Email.
4. Скопировать из **Project Settings → API** URL и `anon`-ключ.
5. Создать `.env` по образцу `.env.example`:
   ```
   VITE_SUPABASE_URL=...
   VITE_SUPABASE_ANON_KEY=...
   ```
6. `npm install && npm run dev`.

На Vercel те же две переменные добавляются в **Settings → Environment Variables**.

Полное описание архитектуры, схемы БД, API и безопасности — в [`backend_documentation.md`](./backend_documentation.md).
